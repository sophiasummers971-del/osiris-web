# Service feasibility, sources and cost assumptions

Public primary documentation checked on **29 October 2026**. Service behavior/prices can change; recheck before a staging proposal or purchase. No live Cloudflare/Supabase plan, allowance, current bill, role, namespace or resource was inspected. Existing paid subscriptions do not imply free capacity or an approved extra project. USD examples exclude tax/FX and are not a quote or spending authorization.

## Consistency and operational comparison

| Candidate                         | Documented capability                                                                                                                                                                                                                                                         | Design implication / limit                                                                                                                                                            |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cloudflare SQLite Durable Objects | Per-object strongly consistent transactional storage; synchronous transaction callbacks; PITR can restore storage within its recovery window [C1](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)                                                  | Suitable tenant coordinator, not a non-rollbackable hardware root. No transaction across objects/services. Root checkpoints must survive a DO restore.                                |
| Supabase Postgres                 | SQL transactions, unique constraints and row locks; default isolation is not a blanket serializable guarantee [S2](https://www.postgresql.org/docs/current/transaction-iso.html) [S3](https://www.postgresql.org/docs/current/explicit-locking.html)                          | Good for resource-local atomic validation/consumption/mutation. Use verified primary, narrow roles and explicit conflict handling. Database restore rolls back local counters/claims. |
| Hybrid                            | Independent service/restore domains can cross-check state                                                                                                                                                                                                                     | Selected staging candidate; more partial-failure windows. No vendor guarantee of a DO+Postgres+R2 transaction. Durable uncertainty protocol and tests are mandatory.                  |
| R2 checkpoint/audit custody       | Strongly consistent object operations and conditional create; retention locks [C3](https://developers.cloudflare.com/r2/reference/consistency/) [C4](https://developers.cloudflare.com/r2/buckets/bucket-locks/)                                                              | Candidate retained evidence/checkpoints, not a multi-object transaction or irreversibly locked admin account. Locks can be administratively removed.                                  |
| Hyperdrive                        | Pools DB access; optional read caching is enabled by default and is not write-invalidated [C5](https://developers.cloudflare.com/hyperdrive/concepts/query-caching/)                                                                                                          | A verified cache-disabled path is mandatory for authorization/effect state; checked-in binding does not establish live caching settings.                                              |
| Supabase Auth / functions         | MFA assurance claims; RLS and function grants; secret/service roles can bypass RLS [S1](https://supabase.com/docs/guides/database/functions) [S4](https://supabase.com/docs/guides/database/postgres/row-level-security) [S8](https://supabase.com/docs/guides/auth/auth-mfa) | Identity/session building block, not exact plan approval. Private functions need explicit caller/tenant checks and grants.                                                            |
| Workers service bindings/secrets  | Private service invocation and runtime secret values [C7](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/) [C8](https://developers.cloudflare.com/workers/configuration/secrets/)                                                           | Useful least-privilege composition, not an individually verified agent or non-exportable signing key.                                                                                 |

No public source retrieved establishes that existing Workers/Supabase secret storage provides the required independent non-exportable Ed25519 authority custody. This is an unresolved vendor/control selection, not a feature assumed available.

## Cost envelope

The illustrative small staging load is **10,000 jobs/month, 30,000 protected operations, at most 200,000 authority RPCs, 1 million billed SQLite row writes including indexes, 5 million row reads, 1 GB authority state, 80,000 checkpoint writes, 300,000 checkpoint reads and 10 GB-month retained R2 data**. These are planning inputs, not measurements of this repository. Each new checkpoint, identity, index, retry and retained manifest must be included in actual staging telemetry.

| Service / dimension  | Published price basis                                                                                                                                                                                                   | Consequence for that envelope                                                                                                                                                 |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workers Paid         | Minimum $5/month; usage allocations and overages apply [C6](https://developers.cloudflare.com/workers/platform/pricing/)                                                                                                | A new eligible account starts with this base; do not assume current account entitlement.                                                                                      |
| DO requests/duration | Paid inclusion: 1 million requests/month and 400,000 GB-s; overage $0.15/million requests and $12.50/million GB-s, with billing-unit rounding [C9](https://developers.cloudflare.com/durable-objects/platform/pricing/) | Request envelope fits only if allocations are otherwise unused. Long in-flight I/O can dominate duration; measure rather than pricing only request count.                     |
| DO SQLite            | Paid inclusion: 25 billion row reads, 50 million row writes, 5 GB-month; overage $0.001/million reads, $1/million writes, $0.20/GB-month [C9](https://developers.cloudflare.com/durable-objects/platform/pricing/)      | Hypothesized small load fits unused allocations; indexes/mutations count. This is not a free-resource or capacity guarantee.                                                  |
| R2 Standard          | $0.015/GB-month, $4.50/million Class A and $0.36/million Class B; included 10 GB-month, 1 million A, 10 million B [C10](https://developers.cloudflare.com/r2/pricing/)                                                  | Envelope may fit unused allowance. Use the documented rounding for overages. More retained data/independent accounts changes the total.                                       |
| Supabase Pro/compute | Pro from $25/month; $10/month compute credit; Micro about $10/month, Small about $15/month [S5](https://supabase.com/pricing) [S6](https://supabase.com/docs/guides/platform/manage-your-usage/compute)                 | New single-Micro paid organization is approximately $25; another Micro project typically adds compute, not another free project. Current organization/credits are unverified. |
| Supabase PITR        | Seven-day retention about $100/month, requires at least Small compute [S7](https://supabase.com/docs/guides/platform/backups)                                                                                           | Illustrative new Pro+Small: $25+$15−$10+$100 ≈ **$130/month**, before Cloudflare and other charges.                                                                           |

A wholly new small paid stack without PITR is therefore roughly **$30/month base** ($25 Supabase + $5 Workers), assuming the stated allocations, one organization/project and no extra charges. With the described Small/PITR setup it is roughly **$135/month base**. These totals **exclude** independent custody accounts/services, KMS/HSM signing, external audit, extra staging/backup compute, AI/provider usage, overages, support/SLA tiers, tax and human review. A production budget cannot be approved until those missing costs and actual workload limits are measured. No currency conversion is assumed.

Free/local service tiers may support disposable experiments; their limits, pauses and lack of recovery/custody proof cannot justify production security or availability. Cost pressure must not remove checkpoints or enable automatic uncertain retries. Prefer a smaller allowed operation set and explicit denial.
