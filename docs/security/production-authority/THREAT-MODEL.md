# Threat model: production authority integration

Repository: `sophiasummers971-del/osiris-web`. Examined version: `45b754eb02a034fd5c13462f6157a3b4685e27f5`. Fresh model for this design mission; no shared cached model was read or replaced. It describes proposed controls separately from source observations.

## Assets, actors and boundaries

Assets: tenant isolation; exact owner intent; provider/DB credentials; immutable plan/contract bytes; consumed identities; monotonic generations; budgets; private evidence; truthful process/effect receipts; retained audit; ability to freeze and reconcile safely.

| Actor                                         | Assumed ability / trust                                                                                                                                                                                                                                          |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Untrusted agent, prompt/tool/document content | Arbitrary hostile requests, forged IDs/signatures, replay, concurrent requests, changed declarations and attempted data exfiltration. Cannot select trusted keys or read protected actuator credentials by design.                                               |
| Authenticated application user                | Can call HTTP/REST/RPC directly, bypass UI buttons and submit arbitrary inputs with a valid ordinary session. Session authentication is not owner approval.                                                                                                      |
| Compromised supervisor workload               | Can replay its own valid proof and race other instances. Production actuator must independently validate grants; giving this workload a provider/DB secret would collapse the boundary.                                                                          |
| Network/runtime failure                       | Delay, loss, duplicates, reordering, partitions, timeout after success, cold start, process crash and partial persistence. Timeouts are uncertainty, not rollback.                                                                                               |
| Deployer / cloud or DB administrator          | Can alter code, bindings, grants, snapshots or retention policy according to privileges. Must be separated from routine execution/reconciliation. Joint administrative or provider compromise is outside the conditional guarantee and remains an explicit risk. |
| Owner and reconciler                          | Distinct enrolled principals. Their signatures are verified independently. A dishonest or compromised reconciler can attest false facts; cryptography does not solve that. Independent observation and custody review are required.                              |

Boundaries: browser/untrusted input → authenticated ingress; ingress → approval/authority; workload → actuator; authority state → independent checkpoint; actuator → actual resource; local receipt → independent observer/audit; routine operator → deploy/restore/custody administration. Bootstrap identity traffic is explicitly narrow and cannot mint an execution capability.

## Source observations, not hypothetical exploit claims

| ID   | Evidence / significance                                                                                                                                                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| O-01 | Worker literal runtime graph has 29 local modules and no Rule Zero import. AI, monitoring, case storage and cron email currently execute through application controls outside the prototype. See [execution map](EXECUTION-BOUNDARIES.md). |
| O-02 | The Node API imports the same appRouter; alternate start commands and host secrets are additional integration surfaces. Existing dependency lint is not a complete-mediation policy.                                                       |
| O-03 | Evidence upload precedes its separate DB transaction; a signed download URL outlives issuance. These are actual two-stage/capability semantics, not atomic fenced effects.                                                                 |
| O-04 | Outbox retries expired `sending` leases. That application protocol cannot be represented as proof that an uncertain Rule Zero operation never executed. No behavior was changed here.                                                      |
| O-05 | The synthetic authority has separately stored but same-host key/records and optional epoch mode. Its earlier tests do not establish protected production custody, live role grants, provider fencing or mandatory host mediation.          |

These observations identify integration blockers. They do not establish an authentication vulnerability or misconfiguration of an uninspected live account.

## Attack paths and required evidence

| Threat                       | Attempted path                                                                                          | Required control / acceptance evidence                                                                                                                                                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Spoofing / confused deputy   | Ordinary JWT/admin email or forged workload ID becomes a plan approval                                  | Stable subject/tenant enrollment, fresh owner challenge bound to exact plan, separate workload audience/key; real negative API tests with valid ordinary sessions and no approval.                                                                    |
| Prompt/tool injection        | Retrieved content supplies SQL, shell, target URL, approval text, provider result or trusted key        | Treat content as data. Typed allowlisted adapters derive resources/charges; no arbitrary network/runner/callback/key parameter. Requests outside schema cause zero adapter effects.                                                                   |
| Approval/contract replay     | Reuse another task/tenant/version/contract, alter plan bytes, refresh an ID                             | Exact signed bindings, permanent unique consumed keys, single-use challenges and shared atomic claims. Cross-tenant/concurrency tests must assert resource effects, not merely a RED return.                                                          |
| Stale generation / rollback  | Restore DB or DO counter with its local witness; use a replacement namespace                            | Independently retained current checkpoint and consumed manifest; pinned authority/resource incarnations; restore begins offline and needs reviewed transition. Rehearse DB-only, authority-only and combined restore; no grant before reconciliation. |
| Check/effect race            | Validate DO token, await HTTP/SQL, then a recovery invalidates it before action                         | Resource-local atomic fence comparison or durable in-flight barrier preventing epoch advancement. Prove actual effect history is linearizable. Plain network admission checks do not satisfy this control.                                            |
| Duplicate/unknown work       | Lose provider or commit acknowledgment, redeliver queue item, reclaim expired lease                     | Stable operation ID, recorded intent, resource deduplication where supported, no automatic resend/takeover. Ambiguous states retain consumption and block affected recovery.                                                                          |
| Privilege bypass             | Direct Supabase REST/RPC, secret/service role, raw SQL, cron or legacy helper avoids gateway            | Effective role/binding/egress tests, no privileged frontend/agent secret, private functions with explicit EXECUTE grants, shared manual/cron claims. A UI-only test is inadequate.                                                                    |
| Audit tampering / truncation | Modify rows/hash head together, delete retention objects, restore evidence                              | Independent signed checkpoints/manifests and locked retained copies under a different custodian. Test real effective permissions and policy-change audit; local hash success alone fails this gate.                                                   |
| Key theft / substitution     | Read runtime key or replace enrollment/pinned public key                                                | Non-exportable signing custody, reviewed rotation, least-privilege workload proof and trusted artifact delivery. Ordinary secret bindings are not an HSM claim.                                                                                       |
| Private-data disclosure      | Broad agent DB read, signed URL reuse, cross-zone redirect, provider egress                             | Actual row/path/bucket/zone/byte limits; fence-aware data delivery where required; no redirect expansion or cached authorization. Previously issued bearer access is an explicit unsupported revocation case.                                         |
| False reconciliation         | Owner and executor reuse a key, or “kill returned true” is accepted as exit                             | Distinct reconciler custody and independently collected process-tree/provider/DB evidence; unresolved request/process blocks affected recovery. A signed assertion of unknown facts remains unknown.                                                  |
| Clock / resource exhaustion  | Roll wall clock backward; flood tenant object, crypto or storage; consume budget after delayed response | Counter epochs, bounded validity and monotonic runtime timers; authoritative time policy; per-principal admission limits and reserved budgets; skew/outage/load tests. Denial under uncertainty is acceptable; fail-open fallback is not.             |
| Administrative collusion     | Root admin restores authority and independent evidence or changes executable code                       | Separation of duties, protected releases and external custody; independent human review. Existing services alone cannot prove immunity to coordinated privileged compromise.                                                                          |

## Safety and liveness claims

The desired safety property is at most one authorized resource effect for each exclusive operation ID under intact trusted authority/resource/custodian state. Useful execution is not guaranteed: crashes before action can leave work permanently quarantined. “Exactly once” useful work, instantaneous cancellation of arbitrary external requests and automatic disaster recovery are not claimed.

A fenced operation linearized before revocation can finish. A later operation must fail at the resource boundary. If a provider cannot define or expose that boundary, its adapter is unsupported for autonomous execution under this policy. Restarting a client, reducing a timeout or retrying a request does not resolve this limitation.

## Independent review requirements

A reviewer other than the implementation author must validate the full entry/sink inventory against a real deployment, workload and role isolation, root/custodian independence, effect linearization, receipt truth and restore controls. They must examine documented vendor limitations in [sources](SOURCES-AND-COST.md), challenge the hybrid protocol's partial-commit windows and observe the [acceptance tests](IMPLEMENTATION-AND-ACCEPTANCE.md). This model and prior same-assistant synthetic tests are not that independent review.
