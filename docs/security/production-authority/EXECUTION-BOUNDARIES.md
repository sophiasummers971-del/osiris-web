# Execution entry points and bypass closure

Scope: source at `45b754eb02a034fd5c13462f6157a3b4685e27f5`. Checked-in configuration describes intended wiring; deployed versions, live credentials, grants, external schedulers, webhooks and dashboard/manual operations were **not** inspected. No claim of complete live-account coverage follows from this repository inventory.

The literal import graph rooted at `worker/index.ts` contains 29 local runtime modules and **zero Rule Zero modules**. `rg` found no supervisor/launcher import in `server`, `worker` or `client/src`. [source-inventory.json](source-inventory.json) retains roots, edges, source hashes and scan limits. The current boundary script checks legacy dependencies, not complete Rule Zero mediation.

“Bypass” below means capable of acting outside the proposed supervisor boundary. Existing authenticated-user, owner, resource and database protections are not declared broken merely because they are separate controls. No production exploit was attempted.

## Reviewable migration rule

Each row must receive a disposition: mandatory fenced adapter, explicitly constrained human/control-plane operation, or disabled/removed from production capability reachability. “Read-only,” “internal,” “scheduled,” “owner-only,” “RLS-enabled” and “already audited” are not automatic exemptions. The bootstrap exception list is explicit and cannot perform protected job effects.

Do not retrofit by wrapping only tRPC admission: cron, signed URLs, direct DB/SDK access, retries, legacy startup and binding credentials would remain bypasses. No source route, credential or policy was changed in this design PR.
