# Proposed acceptance tests and evidence oracle

**Design cases only — NOT executed results.** Existing regression results in [README](README.md) must not be used as evidence that these new database/hosted cases pass. The implementation PR must add the harness/functions in isolated development before any separately approved resource activation.

## Reproducible future harness

Pin source/build, Postgres version/extensions and every resource/role/config digest. Generate ephemeral, distinct owner, contract issuer, agent, authority, checkpoint and observer/reconciler Ed25519 test keys; persist only public fingerprints and signed synthetic evidence. Never commit private keys or load production env files. Use the [one-tenant fixture](synthetic-fixture.json) as input structure, **not as an executable approval**. Generate fresh identities/plan versions for separate healthy trials. For sequential trials on the one fixed resource, observe its current version, bind that version and the new marker into the signed plan's approved-arguments digest, and expect version +1. Never reset the resource to version zero or clear consumed state between trials. The checked-in fixture describes the first empty-resource trial only. Negative mutations share the original signed bytes to prove invalidation; never re-sign a tampered request as the trusted authority.

The future harness has separate processes for two independent supervisors, fixed gateway/registrar, fixed actuator/controller, checkpoint service and independent observer. Workers are disposable fixed binaries with distinct NR-xxxxx identities and denied network/DB access. Expose deterministic test barriers only to a separately authenticated harness control plane, absent from production builds. No agent can choose a callback/runner or invoke a fault hook.

Use barriers at: authority PREPARED; independent intent create/ack; permit registration; immediately before DB gate lock; after gate lock/before consumption; after marker/before audit; before COMMIT; after COMMIT/before response; before completion checkpoint; freeze lock/ack; fence installation/activation; worker stop/session shutdown. Inject one fault at a time and record which side of each barrier actually ran.

For each case, observer takes **before/after consistent primary snapshots** of synthetic evidence views and obtains independent authority/checkpoint manifests plus process-tree/session evidence. Record adapter invocation count independently of worker logs. Do not call a mutating function to query its outcome. Use two DB sessions to hold/race locks and a connection proxy to drop acknowledgments; never run this against the existing OSIRIS project. Same-host local emulation is a development layer, not proof of cloud IAM/restore/custody.

Each result records case/run/tenant/operation IDs, exact artifact/config/fixture hashes, injected fault/barrier, observed row/audit/claim/budget deltas, authority/checkpoint sequence/fence, SQLSTATE or denial class, worker/session status and signed observer challenge. Any missing required evidence yields INCOMPLETE/AMBER, not PASS.

## Completion threshold

All applicable cases need reproducible independent evidence and zero unexplained effects. Every undefined injection, missing harness capability or unconfirmed oracle is UNVERIFIED, not skipped-as-PASS. Run P2-01 and concurrency cases repeatedly with fresh approved identities; report exact trial totals, not only unit-test totals. Proposed performance bounds are reviewed test inputs, not measured service SLOs.

Hosted activation requires reviewed effective grants, no live routing or production credentials, independent retention/restore/host proof and signed owner approval for the exact resource list. Passing local fixtures is insufficient. The external dependency/TCB assumptions and unsolved root attacks must remain AMBER in the report even if all bounded cases pass.
