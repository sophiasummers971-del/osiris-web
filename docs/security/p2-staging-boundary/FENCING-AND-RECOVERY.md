# Resource fencing, evidence and recovery

**Proposed protocol; no hosted implementation or new enforcement result is claimed.** Read [the database contract](DATABASE-CONTRACT.md) and [acceptance cases](ACCEPTANCE-TESTS.md) together.

## Trust boundaries and one-operation dispatch

An external tenant authority (proposed SQLite-backed DO) owns monotonic epoch, per-supervisor fencing sequence and permanently burned identities. An independently administered checkpoint service retains intent/recovery/completion manifests outside both authority and database restore domains. The trusted gateway/registrar, actuator, resource controller and observer have separate credentials and fixed code. Untrusted synthetic workers have none of them, no outbound network and no arbitrary runner/tools.

1. Authority verifies exact Plan Y/owner/contract/agent/Rule Zero admission and canonical tenant routing. In a local authority transaction, it burns exclusive IDs, reserves the one-operation budget and records PREPARED intent with operation/argument/artifact/resource/incarnation/fence hashes.
2. Independent checkpoint service conditionally creates a unique sequence/intent record and acknowledges its exact retained hash/head. Conflict, missing head, stale/forked sequence, failed write or lost acknowledgment quarantines; the authority cannot substitute a local log or create a new empty authority.
3. Authority records the checkpoint acknowledgment, creating an irreversible dispatch intent. The fixed registrar verifies the actual pinned authority/checkpoint receipts and the separate owner/contract signatures, then registers the immutable permit under the resource gate. Registration is not an effect or automatic retry license.
4. Immediately before adapter dispatch, the trusted actuator revalidates online authority lease/fence, current checkpoint/intent and host health using pinned identities, plus monotonic local deadline. It rejects unknown/outage/revocation/timeout and uses only the fixed DB call with a primary TLS connection. Resource transaction independently checks the **resource's current fence** and consumes the permit atomically with the append.
5. After COMMIT, an independently operated observer queries the primary synthetic evidence views and checks effect, consumed IDs, budget, resource version and audit consistency. Observer signs a challenge-bound observation; authority records the outcome and checkpoint service durably retains the completion manifest. Only then report VERIFIED_COMPLETE.
6. Terminate the disposable worker and retain independently observed cgroup/PID/start-identity/exit evidence. No automatic replacement. A worker exit alone is not proof about the DB commit; a DB row alone is not process-tree termination.

There is no atomic commit across DO/checkpoint/Postgres. Each awaited transition needs its own durable pending state. The implementation must not keep an unrecorded in-memory lock over external I/O or assume a private service binding supplies a distributed transaction.

## Epoch and revocation transition

Use a fail-closed barrier, scoped to this single tenant/resource:

| Phase           | Required ordering and evidence                                                                                                                                                                                                                                                                                |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQUEST_FREEZE  | Authority records transition ID, stops issuing dispatch grants and requests the resource controller freeze. If DB/authority is unreachable, return FREEZE_UNCONFIRMED; do not acknowledge revocation as enforced. Existing accepted work may be in flight.                                                    |
| RESOURCE_FROZEN | Controller obtains the same exclusive gate lock used by append. Transactions already owning it finish or time out before freeze commits. Freeze blocks all later append/registration. Receipt includes incarnation, old epoch/fence, resource version and transition ID.                                      |
| RECONCILE       | Independent observer compares all pending/burned intents, actual rows/audit and process/session stop evidence. Missing/contradictory evidence quarantines the tenant; no new epoch can bypass unresolved work.                                                                                                |
| INSTALL         | Owner plus distinct reconciler approve exact transition, consumed manifest, old/new epoch/fence/incarnation, build/target and checkpoint head. Authority and DB install strictly increasing values while both remain blocked. No caller-chosen supervisor or key substitution.                                |
| CHECKPOINT      | Independent service retains transition and manifest; lost/conflicting acknowledgment keeps FROZEN. Publishing an authority head without the matching resource receipt is not activation.                                                                                                                      |
| ACTIVATE        | After verifying all bindings, controller activates only the exact installed resource transition; authority activation follows its acknowledgment. Crash between activations leaves no dispatch permission; recovery resumes the recorded transition after independent inspection. No old permit is rewritten. |

Revocation takes effect for this resource when RESOURCE_FROZEN commits, not when a remote operator clicks revoke. An effect serialized before freeze may commit; an append serialized after freeze must be denied. A partition cannot be converted into a successful stop/freeze receipt. New grants always need authority readiness; leaked/previously registered permits additionally encounter the DB gate. Per-agent revocation uses this same tenant-wide freeze for the initial one-operation scope; no unreviewed partial revocation optimization.

Expiry is checked at the resource authorization guard; no guarantee of retroactively undoing a transaction admitted before expiry. Clock/skew monitoring and fixed deadlines are assumptions to test, never a source of new epochs.

## Failure classification

| Failure window                                                                | Effect/completion classification and permitted next action                                                                                                                                                |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Missing approval, admission, authority/checkpoint/host health before dispatch | DENIED, zero adapter calls. Burned or uncertain claims remain burned. No fallback, automatic request retry or identity replacement.                                                                       |
| Retained intent acknowledgment lost                                           | UNKNOWN_INTENT, quarantine. A timeout is not evidence that no record was created. Independent read/manifest reconciliation only.                                                                          |
| Permit registration or DB dispatch acknowledgment lost                        | UNKNOWN_EXECUTION. Freeze tenant/resource as possible, preserve all identities, observe DB from primary. Never invoke append again to query status.                                                       |
| DB audit insertion fails within append                                        | Entire resource transaction rolls back. External intent remains burned; no success receipt. Independent evidence must establish absence before any fresh job is considered.                               |
| DB COMMIT succeeds but receipt/observer/completion checkpoint fails           | Effect may already exist. NOT VERIFIED_COMPLETE; UNKNOWN_EXECUTION or EFFECT_OBSERVED_COMPLETION_UNCONFIRMED. Freeze/quarantine, retain row/evidence, do not resend.                                      |
| Checkpoint/audit outage begins after a verified intent and accepted dispatch  | An accepted DB transaction may still commit; no promise of zero such in-flight effects. Block all subsequent dispatch and completion claims. Missing evidence cannot be treated as an automatic rollback. |
| Process/DB session kill unconfirmed, late callback or crash                   | STOP_UNVERIFIED plus quarantine. Signal success is not observation. No identity reuse, automatic worker replacement, connection replay or unguarded fallback.                                             |
| Conflicting checkpoint/authority/resource heads or snapshot restore           | Quarantine entire tenant and authority incarnation. Independent recovery transition required; never choose the most convenient head.                                                                      |

A “fresh” online check is a dispatch-time observation, not a continuous proof that an external service stays available through COMMIT. Resource epoch safety comes from the shared DB lock/barrier. Stronger guarantees requiring instant denial for every remote outage during a DB transaction are not demonstrated and need a different resource-integrated protocol.

## Independent completion and reconciliation packet

Retain exact source/config/artifact digests and fixture hash; trust-root enrollment/public fingerprints; signed exact plan/approval/contract and immutable request digest; authority epoch/fence/claim sequence; independent intent/checkpoint records; DB gate/permit/claim/audit/effect projection; expected versus observed row counts; transaction outcome evidence; supervisor/worker identities and independently observed process/session termination; failure injection position; decision/error class and absence of automatic retry.

The observer is a distinct operator/process on an independently administered host, owns read-only evidence credentials and its signing key, and cannot execute jobs. Observations bind a fresh verifier challenge, tenant/run/operation, target/incarnation/build, current authority/checkpoint heads and DB evidence hashes. Same-host logs, same-author self-signed receipts, arbitrary agent screenshots, `pg_terminate_backend` without observed disappearance or a successful kill return alone do not count. No production records, raw secrets, headers or private keys enter evidence.

Reconciler verifies actual effects/absence against **all** burned intents and sequences, including orphaned prepared records, not only the latest local DB rows. Owner and reconciler are distinct enrolled keys/subjects. Confirmed absence does not release an old job; a new independently approved plan/contract/job/operation is required, preserving the failed/uncertain predecessor. Unresolved intents block the whole tenant in this initial scope.

## Restore and root boundary

A database-local fence can be rolled back with its database. Therefore this staging proposal **forbids restoring an active registered endpoint**. The separately authorized restore controller must first freeze external dispatch, quarantine endpoint/network access, close and independently confirm old sessions/workers, and preserve current independent manifests. Restore only to a new unregistered endpoint/incarnation with no enabled workload login/network route. Reconcile all consumed identities from independent evidence, enroll new credentials/pins, obtain exact owner+reconciler recovery approval, then run the activation protocol. Old endpoints and identities remain denied.

Long-lived sessions and queued SQL must be proved unable to reach the restored endpoint. Merely changing a database UUID in a restored row does not prove quarantine. Lost shutdown confirmation blocks activation. No automatic endpoint discovery, DNS failover, credential fallback or reset-to-empty authority.

An **invisible privileged in-place rollback while old actuator sessions remain reachable is not solved by this design**. A test that demonstrates duplicate authority under that attack is a blocking finding, never waived as a pass. The staged acceptance gate requires externally enforced restore quarantine; if the chosen managed service/operator boundary cannot demonstrate it, hosted activation is blocked. Simultaneous compromise/rollback of authority, checkpoint, DB and privileged host remains outside the tested prototype and keeps production AMBER.

Retained intent/tombstones survive artifact rollback and tenant retirement. Proposed synthetic evidence retention is 30 days for full test traces, at least 365 days for signed run/recovery manifests, and consumed identity tombstones for the run's replay lifetime until independently approved retirement. Custodian/privacy owners must approve actual retention and deletion; these periods are not preapproved legal policy.
