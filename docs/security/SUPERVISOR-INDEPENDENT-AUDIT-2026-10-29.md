## Findings and narrowly scoped fixes

Severity is qualitative and scoped to the stated trust model; these are not assigned CVEs.

| ID / severity                                                                   | Reproduction and impact on original source                                                                                                                                                                                                                                                                                                                                                                                         | Repair / residual boundary                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F-01 **High** — spawn after cancellation                                        | Deterministically hold the real worker-file copy, invoke `stopAgent` or `close`, then release copying. Both cases returned RED but still spawned one revoked child. Its phase remained STARTING, no exit evidence existed, and the cached pre-spawn stop result did not kill it. Test-only cleanup had to terminate the known disposable PID. This was a real lifecycle escape from cancellation, not a successful tool operation. | Recheck revocation, health and closing immediately before `spawn`, after all asynchronous preparation. Both regression variants now return RED with **zero spawned workers**. No automatic retry/replacement was introduced.                                                                                                     |
| F-02 **Medium** — expired signed action reaches effect                          | Delay the adapter's actual file-stat completion by 1,150 ms. The worker's signed request lived 1,000 ms; the configured operation/lease remained live. Original code returned **GREEN with one effect** after that request expired. No clock or authority signature was forged.                                                                                                                                                    | Recheck the immutable signed request's issuance/expiry at every adapter permission check, including immediately before effects after I/O. Same test now returns RED with **zero effects**.                                                                                                                                       |
| F-03 **Medium** — fabricated exit assurance on spawn failure                    | Test-only replacement of the host spawn call attempted a nonexistent executable. The real spawn failed with no observed PID, yet the journal/result said `PROCESS_EXIT_OBSERVED`, `pid: null`, `exitCode: -2`, `observedExit: true`. That is not valid termination evidence for a worker.                                                                                                                                          | Require an observed positive PID for process-exit evidence and observed-spawn counting; otherwise record `PROCESS_SPAWN_FAILED`, `observedExit: false`. The corresponding regression passes without relaxing admission.                                                                                                          |
| F-04 **High production isolation gap** — native descendants survive parent stop | A kernel-profile-only probe executes the exact bootstrap prefix and then native `fork` / non-thread `clone`. Both created a bounded disposable descendant; after terminating the parent, the descendant was still alive. **This is not a demonstrated escape through the fixed Node worker API.** It establishes that the kernel layer itself did not enforce the claimed no-descendant boundary.                                  | Deny `fork`/`vfork`, restrict `clone` to `CLONE_THREAD`, and deny `clone3` with `ENOSYS` so libc can use its inspectable thread-only fallback. Actual fork/process-clone probes now receive **EPERM**; normal Node startup and all worker tests still pass. General cgroup/process-tree lifecycle control remains unimplemented. |

## Verified protections versus unresolved production controls

| Boundary                                       | Evidence and production recommendation                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Plan/approval/contract integrity               | Changed plans, wrong signing authority, owner/tenant/step mismatch and expanded scopes are denied before worker creation. Existing signature/admission tests remain passing. Real owner enrollment, key custody, hardware protection, early revocation and automatic plan-version supersession are **unimplemented production controls**. The supervisor itself holds agent signing keys, so it can act as those identities; this is a trusted-host design assumption, not external agent independence. |
| Identity, capabilities and resources           | Fixed entry point, per-worker IPC/keys, host-owned registry and adapter resource/zone checks remain verified against synthetic requests. No tested post-patch bypass through that interface succeeded. Untrusted code in the supervisor process, compromised pins/host, arbitrary native malware, OS filesystem isolation, inherited-FD analysis and total-memory/rate hardening are **not certified**. The local same-UID capability-less profile is not dedicated-user isolation.                     |
| Process lifecycle and tree                     | Existing actual PID/close, crash, timeout, concurrent-worker, late-callback, hung-audit and unconfirmed-stop tests still pass. New kernel policy denies observed native process creation while allowing runtime threads. There is **no general cgroup/process-group tree controller**, restart/orphan reconciliation, external watchdog or safe arbitrary-child adoption. If the fixed-code/creation boundary is bypassed, universal descendant termination is not established.                         |
| Replay and recovery — **High production risk** | Fresh characterization proves that two independent state directories can accept the same tenant plan/job when the trusted issuer reissues contracts for their independently generated keys. Local atomic claims are not tenant-global once-only enforcement. Add a shared transactional identity/claim/budget service and recovery semantics before multi-supervisor use. No such service/database was introduced in this mission.                                                                      |
| Preserved/lost storage                         | Restart against preserved nonempty state is rejected rather than silently clearing it. Lost replay storage blocks an admitted worker before effects and leads to actual stop. This is fail-closed behavior, **not implemented recovery**. Deleted/rolled-back claim files, state tampering by a privileged host and distributed restore remain outside guarantees. Failed/cancelled reservations and identities remain burned; capacity/memory reclamation needs a reviewed lifecycle design.           |
| Audit and availability                         | Ordinary denied operations never produce a tool effect; failed/hung journals deny effects and do not prevent kill delivery. Local fsync acknowledgment is not external tamper-resistant evidence. An underlying timed-out write may finish later. The observed safe startup denial under load means acceptance/availability is not guaranteed by a 200 ms budget; do not weaken it merely to make fixtures green. Establish an operational latency envelope and independent append-only evidence.       |
| Rule Zero integration                          | Current provider/credential/quota observations are **synthetic PASS fixtures**, not actual production authorization. The fixed base commit comparison does not attest an executing repository binary. Real tenant/resource authorization, provider state, trusted clocks, actual usage metering and complete mediation of every external tool path remain production gates.                                                                                                                             |
| Incomplete orchestration                       | Dependent steps remain blocked without independently verified completion evidence. Synthetic budget units are not model-token billing. No automatic agent replacement exists; manual replacement requires new approved identity/plan/contract material. Already-completed effects cannot be undone; RED alone is not confirmation of process termination.                                                                                                                                               |

The separate characterization test passes when it observes the **absence** of tenant-global replay protection. It is deliberately diagnostic and does not turn that unresolved risk GREEN.

## Recommendations and rollback

Keep all PRs draft and this branch non-production. First, have a reviewer independent of the implementation author rerun the original-source reproduction and inspect these small fixes. Next establish hardened OS isolation/tree supervision, shared identity/replay/recovery policy, real owner/provider authorization and externally durable audit. Only then consider broader workload or production proposals under a separate authorization.

PRs #47–#50 were rechecked after source CI: heads, bases, draft/open states, titles and descriptions were unchanged.

Rollback is a normal revert on the new audit branch only. Do not reset or modify PRs #47–#50. The mission changed no production credentials, databases or deployments. Disposable processes were stopped or explicitly cleaned up by the test harness; no live agent was connected.
