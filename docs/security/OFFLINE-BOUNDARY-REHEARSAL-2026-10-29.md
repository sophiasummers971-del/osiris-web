## What actually ran

[Offline model](../../scripts/rule-zero/offline-boundary.mjs), [31 tests](../../scripts/rule-zero/offline-boundary.test.mjs), and [fixed negative probe](../../scripts/rule-zero/offline-permission-probe.mjs). No new dependencies, migrations, workflow or application configuration.

The host-only factory creates **new temporary empty SQLite fixtures**; it cannot accept a connection URL or migrate an existing database. Separate resource, external-authority and checkpoint directories model distinct domains, but share the same host/root administration. All keys are generated per test in memory; only public pins/signed synthetic records can be exported.

The resource verifies existing Plan Y/contract signatures, signed agent action, exact tenant/target/tool/zone/arguments, one-use IDs, fixed source-derived ruleset and current epoch/fence. Its SQL transaction atomically appends one marker, version and audit row. Intent is committed separately first. Observer SQL connection is read-only with an actual SQLite authorizer denying DML, DDL, PRAGMA changes and ATTACH. **This is a protected wrapper/connection, not PostgreSQL role isolation.**

An append return means EFFECT_COMMITTED_COMPLETION_PENDING. Completion needs a matching separately signed synthetic observation and retained checkpoint; neither a function return nor a worker log suffices. Errors/lost acknowledgments leave INTENT/unknown state; subsequent dispatch denies. Recovery freezes first, verifies exact signed snapshot/next epoch, retains burned records and requires fresh approved work. Repeating completion publication does not rerun an effect.
